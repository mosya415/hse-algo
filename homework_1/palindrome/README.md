# Задача 1. Палиндром

Решение в `palindrome.py`, тесты в `test_palindrome.py`.

    echo 121 | python3 palindrome.py
    python3 test_palindrome.py

## Идея

Строки нельзя, поэтому цифры достаю арифметикой: `n % 10` даёт последнюю цифру, `n // 10` её отбрасывает.

Разворачивать число целиком незачем (да и переполнение в других языках), достаточно развернуть правую половину и сравнить с левой. Пока `number` больше развёрнутого `reversed_tail`, переношу в него по цифре с конца числа. Как только половины сравнялись, цикл заканчивается.

Дальше два случая. Если цифр чётное количество, половины должны совпасть. Если нечётное, в `reversed_tail` лишняя центральная цифра, её отбрасываю: сравнивать её всё равно не с чем.

Числа с нулём на конце проверяю отдельно: ведущих нулей в записи не бывает, значит первая и последняя цифры разные. Кроме самого нуля.

## Сложность

Цифр у числа n примерно log10(n), а цикл убирает по цифре за итерацию и делает их вдвое меньше. Отсюда время O(log n). Память O(1): две переменные.

## Пример: 1234321

| Шаг | `number` | `reversed_tail` |
|-----|----------|-----------------|
| старт | 1234321 | 0 |
| 1 | 123432 | 1 |
| 2 | 12343 | 12 |
| 3 | 1234 | 123 |
| 4 | 123 | 1234 |

На пятой проверке 123 > 1234 уже неверно, цикл выходит. Цифр нечётное количество, поэтому 123 != 1234, зато 1234 // 10 = 123 совпадает с `number`. Ответ True, отброшенная четвёрка была центральной цифрой.

Если взять 1234329, то после тех же четырёх шагов `number` = 123, а `reversed_tail` = 9234. Ни 9234, ни 923 не равны 123, ответ False.

## Тесты

Примеры из условия, однозначные числа, ноль, числа с нулём на конце, палиндромы чётной и нечётной длины. Из неочевидного: замена центральной цифры палиндром не ломает (1234321 и 1235321), а расхождение в одной зеркальной паре ломает (1234329, 1934321, 1244321). Плюс сверка со строковой проверкой на всех числах до 1000.
